## 3. 当前架构与目标之间的差距

### 3.1 已存在的结构

```text
设备模拟器 ── WebSocket ── main.py ── MockProviders ── 文本状态帧
                                    │
                                    └─ hello 时读取自主脚本的第一句 say

IM 合成请求 ── im.py ── NiulaiBrain.handle_user_text
                           ├─ 内存 PersonaFSM
                           ├─ 内存 im_outbox
                           └─ 内存 McpBroker 队列

三个 Arduino 硬件检查草图：未与上面的产品闭环集成
```

`brain/app/main.py:12–15` 的 `_speak` 仅发出 `tts start / sentence_start / stop` 三条 JSON，没有合成、编码或发送音频二进制。`brain/app/providers.py:4–21` 仅用 UTF-8 解码模拟 ASR，并返回固定文本。握手在 `main.py:59` 明示 `mock-utf8`，这与协议切片定位一致，但不能当作真实语音链路验收。

当前没有 Web 排练台。本报告的“前端”只评价该 Web 界面；设备屏幕、眼神、口型和动作反馈归入体验及嵌入式维度，不把它们重复计入 Web 分数。

当前没有持久数据库、迁移或人格记忆实现。`brain/app/models.py:6–31` 是内存数据模型，`brain/app/brain.py:22` 和 `brain/app/mcp_broker.py:11–12` 是进程内列表。mock 阶段选择内存合理；数据库维度的零分是面向新目标的缺口，不能写成“现阶段不用数据库就是 bug”。

### 3.2 硬件草图的实际边界

- `firmware/niulai-quad-servo-test/niulai-quad-servo-test.ino:32–35` 在写入舵机脉宽后调用 `delay(holdMs)`；`:60–64` 包含 900 ms 的保持动作。它是轮流摆动检查程序，没有产品级 Safety、动作取消或 MCP 调度。不能把这个阻塞循环直接作为要求快速抢占的产品执行器。
- `firmware/niulai-hcsr04-test/niulai-hcsr04-test.ino:23–35` 用超声回波计算距离；`:53–60` 将结果输出到串口。它没有证明“有人/无人”的判定。远距离或无回波不能直接等于无人，遮挡、静止人员和测量故障必须被纳入人员状态设计。
- `firmware/niulai-tft-spk-test/niulai-tft-spk-test.ino` 是屏幕/扬声器检查草图；不能据此认定真实 ASR/TTS、嘴眼动作同步或可抢占播放已经完成。

### 3.3 必须消除的设计冲突

09-01 的双板文档在 `docs/architecture-niulai-espclaw-xiaozhi-2026-09-01.md:182` 把“妈妈”定义为 `PUBLIC_ALIVE` 的进入动作，`:333–337` 随后允许公开语音会话。这与本轮沿用的牛来设定冲突：**有人时保持机械玩具；喊“牛来”只机械回答“妈妈”；只有确认无人后，才恢复私下有性格的活动和吐槽。**

09-05 的 `docs/architecture-niulai-local-brain-2026-09-05.md:5–13` 已将路线调整为单板加本地大脑，应保留这条实现路线。新设计需要进一步明确：板端拥有最终的人员/安全/人格执行裁决，电脑只能提议内容和动作，不能依靠网络往返完成装死、停止或取消旧语音。旧文档中“公开复活”的状态转换不再作为新产品的验收标准。

## 4. 五项优先代码发现

优先级中的 **P1** 表示应该优先修正的实现问题或闭环阻碍，**P2** 表示应补齐的可靠性问题。后文“P0 门禁”指演示前必须通过的交付条件，两者不是同一种计数。

### R-01 / P1：语音路径绕过 FREEZE 和统一人格规则

**位置：** `brain/app/main.py:82–89`；对照 `brain/app/brain.py:40–49`。

**触发：** 默认 FREEZE 下，通过 WebSocket 发出 `listen.start`、UTF-8 编码的“牛来”、`listen.stop`。

**实测：** STT 返回“牛来”，LLM/TTS 返回“嗯，我在。”；同一 brain 的 IM 入口返回“……”。原因是语音直接调用 `providers.reply()`，没有经过 IM 使用的 `handle_user_text()`。

**影响：** 同一个角色对不同入口执行不同规则；冻结时仍表现出自然回答，也没有确定性的机械“妈妈”应答。更换真实 LLM/TTS 后，这个绕行会继续存在。

**修正与验收：** 所有入口统一为事件和意图；板端最终决定允许输出。自动测试覆盖每种人格状态下的语音、IM、自主事件，并在真实播放中验证插入有人事件后旧语音不会续播。

### R-02 / P1：无人活动缺少恢复、持续调度和设备执行

**位置：** `brain/app/main.py:67–74`、`brain/app/brain.py:16–17,24–36`、`brain/app/persona.py:13–17`、`brain/app/mcp_broker.py:14–18`。

**触发：** 正常启动服务，等待无人活动；或手工进入 SECRET_ALIVE 后建立 WebSocket 连接。

**证据：** 默认状态为 FREEZE；距离入口只会进入 FREEZE，没有实现恢复。合成探针连续三次提交 100 cm，状态仍为 FREEZE。`autonomy_interval_s` 仅被保存，未参与运行调度。hello 只发送脚本第一句 `say`，其他动作没有进入设备传输；队列没有出队、MCP RPC、ACK 或动作完成处理。

**影响：** 已有自主测试证明一次连接时可输出文字，不能证明机器人会等待、观察、活动、被打断和恢复。即使接通真实语音，它也仍缺少持续生命循环。

**修正与验收：** 建立受人员状态约束的非阻塞行为调度、统一执行队列和设备结果回传；以“无人 → 短活动 → 人进入 → 立即装死 → 机械妈妈 → 人离开 → 延迟恢复”的完整序列验收。先用设备模拟器，再由目标硬件重复测量。

### R-03 / P1：动作接口接受底层参数和无限制 TTL

**位置：** `brain/app/mcp_broker.py:23–47`。

**触发与实测：**

```json
{"verb":"walk","dir":"forward","ttl_ms":999999999,"pulse_us":2500}
```

上述参数得到 `ok=true` 并被记录、入队；`dir="invalid", ttl_ms=0` 也被接受。当前只检查 verb 与可转换的非负 TTL，其他字段原样复制。

**影响：** 与 09-05 文档“禁止 pulse_us”和语义动作边界不一致。在接入实际执行器前必须补齐，否则下游可能接收到超时长动作或不应出现的底层控制字段。此次探针没有发送到硬件。

**修正与验收：** 对每个动作定义枚举参数、范围和 TTL 上限；拒绝未知字段、原始 PWM、旧状态版本及过期动作。桌面和板端都需要验证，目标硬件确认拒绝时没有执行器输出。

### R-04 / P1：IM 请求没有可信来源和重复事件控制

**位置：** `brain/app/im.py:47–56,59–66`；默认监听地址见 `brain/app/__main__.py:6`。

**触发：** 在 SECRET_ALIVE 中向飞书入口提交两次相同 event_id 的合成文本事件，不附签名或认证信息。

**实测：** 两次均返回 200，`im_outbox=2`、walk 队列长度为 2。入口没有验证来源签名、发送者控制权限或重复事件；也没有真实平台出站投递证据。

**影响：** 任何能访问当前入口的请求方都能产生意图；平台重试会重复排入动作。现有影响限于内存，接入真实发送和控制之前需要完成适配器边界。

**修正与验收：** 保留明确的本地 mock 模式；真实模式缺少凭据时拒绝启动对应外部入口。验证平台请求、控制者权限、事件 ID 去重，区分请求已接收、动作已接受与实际已完成。用合成重复事件验证一次执行，并在实际平台环境验证签名和回调。

### R-05 / P2：错误 JSON 类型会异常终止设备连接

**位置：** `brain/app/main.py:46–51`。

**触发与实测：** 连接后发送合法 JSON `[]`，产生 `AttributeError: 'list' object has no attribute 'get'`；当前仅捕获 JSON 语法错误，未验证对象类型。

**影响：** 不符合预期类型的消息不能得到受控错误，影响连接稳定性。另有相关静态缺口：`main.py:38–41` 持续累积录音，没有累计字节或录音时长上限；本轮没有执行内存耗尽试验。

**修正与验收：** 入口使用严格消息 schema、帧大小和录音总量限制，规定非法状态顺序的处理。测试数组/null/未知 type、重复 start/stop、超长录音和断线，确认可预测地拒绝或关闭连接且能重新建立健康会话。

## 5. 可复算评分标准

### 5.1 通用计分规则

每个维度包含 5 个子项，每项 0–4 分。只记本轮能定位到的实现与证据；设计文本本身不能获得实机或量化等级。

| 子项分数 | 证据成熟度 |
|---|---|
| 0 | 没有目标能力的实现，或未找到可核验的实现证据 |
| 1 | 有片段、mock、草图或局部逻辑；尚未形成目标集成 |
| 2 | 有与该子项目标相符的集成自动测试证据 |
| 3 | 在指定目标硬件/交付环境中完成验收，有配置、结果与记录 |
| 4 | 在目标环境中重复量化验证，包含适用的故障、重试、恢复和边界情形 |

达到等级必须满足较低等级的要求。mock 测试只为它实际覆盖的子项得分，不能替代真实音频、物理停止或人员识别证据。Web 与数据库等子项的“实机”指交付用电脑、浏览器和设备连通环境，不要求每项直接控制硬件。

```text
维度分 = 五个子项分数之和 / 20 × 100
总分 = Σ（维度分 × 维度权重）
```

## 6. 面向交付的 P0 阻塞与修正顺序

| 顺序 | P0 工作 | 完成条件 | 验证方式 |
|---|---|---|---|
| 1 | 固定故事与状态权威 | 机械“妈妈”不导致公开复活；确认无人后才可秘密活动；板端有最终输出权限 | PRD/SPEC 一致性审查；全状态事件表测试 |
| 2 | 建立板端安全基础 | 未确认人员状态、掉线、异常或停止请求时能停止动作并取消不应播放的语音 | 非阻塞固件测试；目标板测停止/静音延迟；保留原始测量和失败次数 |
| 3 | 修正入口与动作合同 | R-01、R-03、R-04、R-05 关闭；模拟入口和实际入口执行同一边界 | 精确回归上述探针；事件重复/越权/超限/断线注入 |
| 4 | 接通一条真实短表演 | 有实际声音和有界动作，具备动作接受、完成、取消状态；R-02 闭环 | 设备模拟器端到端测试后，在目标实物上录制与测量 |
| 5 | 完成秘密活动与前后呼应 | 可无人等待、自主短活动、装死、机械应答、离场恢复；有限记忆影响后续表现 | 重复完整场景；检查长时间无输入、重复呼叫和恢复后的旧动作清理 |
| 6 | 补齐排练台与持久数据 | 页面显示真实/模拟、当前权威状态及失败原因；记忆和事件具备幂等、容量和恢复约束 | 页面集成验收；进程中断/重启、重复事件、数据库容量与删除验证 |
| 7 | 量化演示验收 | 达到门槛且全部关键门禁通过 | 按 PRD/SPEC 的场景、样本量与指标保留可复核记录 |

先把一个可靠、可打断、有反差的短场景演好，再扩展台词和动作种类。行为丰富度不能替代人员判断、停止和声音取消；前端的“已发送”也不能显示为机器人“已完成”。

## 7. 演示准入标准

建议演示准入同时满足以下条件，任意一项不满足都不能仅凭加权平均放行：

1. 总分 **≥ 75 / 100**；每个维度 **≥ 60 / 100**，包括 Web 排练台。
2. 生命感体验、嵌入式、安全与边界三个维度分别 **≥ 80 / 100**。
3. PRD/SPEC 定义的所有关键门禁通过，包含真实音频、正确机械应答、确认无人后的恢复、板端停止/静音、越权拒绝、断线与重试恢复。
4. 证据包含目标硬件和软件版本、参数、尝试总数、失败次数、时延分布及录像/日志关联；不能只选择成功的一次。
5. “装死/停止时间达标”“真实人员判断”“实际声音和动作同步”必须实测；尚未测量的项目保留未通过状态。

本次没有实施硬件操作，也没有验证商用品质、机械安全、传感器覆盖或真实平台连通。上述门槛是后续设计与开发的验收目标，不是本轮已经达到的结果。
